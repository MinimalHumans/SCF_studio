# Building the Hollow Creek fixture

```sh
python fixtures/build/build_fixture.py            # build it
python fixtures/build/build_fixture.py --check    # verify, write nothing
python fixtures/build/dump_fixture.py             # .scf -> source
```

The build takes **three inputs and no existing fixture**:

| | |
|---|---|
| `spec/scf-schema.sql` | The published DDL — the same artifact a third party gets, generated from `initDatabase()` and checksummed |
| `hollow_creek.data.json` | The authored entity content: 375 rows across 71 tables |
| `hollow_creek.fountain` | The screenplay, via `screenplay_body.py` |

`build_fixture.py` writes `fixtures/hollow_creek.scf` and copies it to
`scf-app/public/`. The two must stay identical — one is what the
conformance suites open, the other is what the demo fetches — and CI
asserts it.

## The loop

Author in `scf-app` → `dump_fixture.py` → **review the JSON diff** →
`build_fixture.py` → commit both.

That middle step is the point. The fixture is a conformance artifact
whose exact content eleven suites assert against, and until 0.35 a pull
request that changed it showed a single line saying a binary file
differed. Now it shows which rows moved.

## Reproducible means content, not bytes

Two SQLite files with identical content can differ byte for byte — page
allocation, freelist state and vacuum history are not part of what the
file says. `--check` compares content: every table, every row, every
column, reporting the first divergence. That is the same comparison
`spec/conformance.md` §3 uses for round-trip integrity, for the same
reason.

The checked-in `.scf` is still the artifact. It is what the suites open
and what `SHA256SUMS` covers; this directory is how it is produced and
how a change to it is reviewed.

## `screenplay_body.py`

Generates `screenplay_lines` from the screenplay it carries as data, and
writes `hollow_creek.fountain` as a **second output** — the fountain
file is generated by it, not read by it. Parsing Fountain here would be
a second implementation of `scf-core`'s tokenizer, free to drift from
it. One source, two outputs.

It is idempotent, and rebuilds the lines wholesale on every run.

## What is not in the JSON

`screenplay_lines` and `screenplay_version_lines`, because
`screenplay_body.py` owns them. `sqlite_sequence`, because SQLite
maintains it and explicit ids restore it. Nulls, because an absent
column and a null one insert identically and carrying every null would
bury the content that matters.

Row ids and timestamps **are** preserved. Row ids are file-local (spec
§6.2) and mean nothing outside this file, but preserving them is what
makes the rebuild deterministic and the diff legible.

## Before you change what it contains

Read [`history/README.md`](history/README.md). Several properties are
load-bearing and none of them is annotated in the data file: scene 12 is
pinned, name anchors are relied on by both suites, scene numbers are
deliberately not sequential, and some gaps exist on purpose. Then read
`docs/conventions.md` §8.
